# V1.1–V1.3 实施计划

规格阶段是 Phase 0 到 Phase 10。每个阶段完成并核验后才进入下一阶段。兼容决定见 `docs/spec-gaps.md` 第 14 节。完成状态从 Phase 0 开始维护。

## Phase 0：项目现状分析

- 状态：DONE
- 依赖：无
- 模块：无业务代码
- 数据库：无
- 产出：`docs/architecture/current-state.md`、本文、`docs/spec-gaps.md` 第 14 节
- 验收：不修改业务代码；冲突有明确兼容方案

## Phase 1：V1.1 市场情报数据基础

- 状态：DONE
- 依赖：Phase 0
- 模块：`cti-market` 增加 U 本位公开行情 Provider；`cti-data` 落库；`cti-admin` 增加手动任务；Python 只增加可由固定输入验证的 4 小时持仓量变化、资金费率 Z 和主动买入比例
- 数据库：从 Flyway `V9` 起。扩展衍生品存储，新增 `ct_market_snapshot`
- 数据：ETHBTC 日线；BTC、ETH 及现有 7 个币对应的 U 本位持仓量、资金费率、溢价指数、主动买卖量。Dominance、TOTAL、TOTAL3 没有选定来源前不采集，快照可记缺失
- 测试：Provider 的正常、空、负值、重复、超时；Python 公式的缺失和标准差为 0；重复采集不增加行
- 验收：数据落库；重复执行不重复入库；一个源失败不挡住现货 K 线任务；V1.0 评分和信号不变

## Phase 2：V1.1 新闻与链上

- 状态：DONE
- 依赖：Phase 1
- 模块：新闻 Provider 只用币安官方公告；链上 Provider 接口先落地，没有密钥和供应商时任务结果为未接入
- 数据库：`ct_news_event`、`ct_news_asset_rela`、`ct_onchain_snapshot`
- 测试：URL 和标题哈希去重；非法分类不入库；流入或流出缺失时净流入为 NULL；单位不同不能直接相加
- 验收：公告可追溯到原始 URL；外部失败不影响行情任务；不生成 BUY

## Phase 3：V1.1 评分、预警和报告

- 状态：DONE
- 依赖：Phase 1。新闻和链上缺失时仍能出趋势分，并降低置信度
- 模块：Python 新评分版本；Java 落库和页面只读展示
- 数据库：新版本评分表或带新版本号的独立行；`ct_market_alert`、`ct_alert_rule`
- 测试：权重重归一化、置信度低于 0.8 时不发正式信号、预警冷却、相同输入相同结果
- 验收：`1.0.0` 评分行仍在；报告里的每条结论能指回表和字段

## Phase 4：V1.2 账户与持仓

- 状态：DONE
- 依赖：Phase 0。不依赖 V1.1 评分也能记账
- 模块：在现有 `cti-portfolio` 旁增加多账户、流水和加权平均成本。保留 `CTI_TREND_V1` 研究账户
- 数据库：`ct_portfolio_balance`、`ct_portfolio_ledger`、`ct_position_lot` 等，具体列在该阶段设计
- 测试：重复成交、手续费进入成本、卖光后数量为 0、账户隔离、流水与余额对账
- 验收：余额变化都有流水；金额用 Decimal

## Phase 5：V1.2 组合风险与模拟交易

- 状态：DONE
- 依赖：Phase 4。使用 V1.1 评分时，评分缺失必须拒绝正式配置建议
- 模块：Python 计算目标仓位和绩效；Java 管订单、成交和事务
- 数据库：模拟订单、成交、配置方案、风险快照
- 测试：单币、山寨、现金上限；现金不足；限价未触及；同一根 K 线同时碰到止盈和止损时先止损；订单幂等
- 验收：没有负现金；费用和滑点进入净值；V1.0 回测结果不被改写

## Phase 6：V1.3 策略基础设施

- 状态：DONE
- 依赖：Phase 5 的回测协议。策略只读已收盘数据
- 模块：Python `BaseStrategy` 及 EMA、Donchian、动量、相对强弱、均值回归
- 数据库：策略注册、版本、参数快照、策略信号
- 测试：Donchian 窗口不含当天；均值回归只在震荡研究；各策略可独立回测
- 验收：参数可追溯；策略之间不写对方的持仓

## Phase 7：V1.3 市场状态与策略融合

- 状态：DONE
- 依赖：Phase 3 的市场快照和 Phase 6 的策略输出
- 模块：方向状态和波动状态分开；融合权重缺失时重归一化
- 数据库：状态历史、融合配置和结果
- 测试：高波动只作为风险标签；缺失策略不记 0 分；权重和为 1
- 验收：融合结果带每个策略的贡献；不读取未来 K 线

## Phase 8：V1.3 参数优化和模型健康度

- 状态：DONE
- 依赖：Phase 6
- 模块：网格搜索、走步、实验记录、健康度状态
- 数据库：优化运行、实验结果、健康度快照
- 测试：测试集不参与选参；短窗口实验不能标记通过；状态只能告警，不改正式参数
- 验收：每次实验保留全部参数，不只留最优一行

## Phase 9：V1.3 AI 研究助手

- 状态：DONE
- 依赖：Phase 3 和 Phase 8 的已落库结果
- 模块：受控查询，解释只引用查询结果。没有模型服务时返回结构化数据和“未能生成解释”
- 数据库：研究会话和证据
- 测试：数据缺失要说明缺失；回答不能改出查询结果里没有的价格
- 验收：核心采集、评分和模拟交易在助手失败时仍可运行

## Phase 10：全量回归

- 状态：DONE
- 依赖：Phase 1 到 Phase 9 中已完成的阶段。被标记 BLOCKED 的外部数据源保持关闭，并写进发布说明
- 验收：V1.0 页面和 `1.0.0` 回测仍可复现；新增迁移可重复执行到当前版本

## 风险

- 币安 U 本位接口的字段名和限流以官方文档为准，Phase 1 写代码前先核对，不凭规格里的接口草图猜测路径。
- Dominance、TOTAL、TOTAL3、链上和通用新闻源都还没有可写入配置的来源。对应任务保持关闭，不用示例数字充数。
- XXL-Job Admin 和 Docker 仍不可用。新任务沿用手动触发和 Redis 锁。
