# Crypto Trend Intelligence 产品设计方案
## V1.1 / V1.2 / V1.3

## 一、产品定位与版本目标

CTI 是一个面向 BTC、ETH 和主流山寨币的量化趋势分析与投资决策辅助系统。

核心目标不是预测某个币明天一定涨还是跌，而是通过市场结构、价格趋势、资金行为、市场情绪和风险状态，回答五个问题：

1. 当前加密货币市场处于什么状态？
2. 哪些币正在形成上涨趋势，哪些币正在走弱？
3. 当前行情变化背后的主要驱动因素是什么？
4. 如果持有某个币，应该继续持有、减仓还是退出？
5. 当前市场环境下，应该采取什么样的策略和资金配置？

版本演进：

- V1.0：建立基础趋势分析和回测能力。
- V1.1：建立多维度市场情报与趋势解释能力。
- V1.2：建立组合管理、资金管理和模拟交易能力。
- V1.3：建立市场状态识别、策略自适应和智能研究能力。

基本原则：

- 价格和成交量是核心事实数据。
- BTC 市场状态是整个市场的重要风险锚点。
- 山寨币需要结合 BTC 相对强弱判断。
- 情绪、新闻、链上数据属于辅助信息，不能直接替代价格趋势。
- 所有策略必须经过历史回测和样本外验证。
- V1.0～V1.3 均以研究和决策辅助为主，不自动执行真实交易。

# 二、V1.1：市场情报与趋势解释系统

## 2.1 产品目标

V1.0 能回答：

- BTC 趋势如何？
- ETH 是否值得关注？
- SOL 当前评分是多少？
- 某个币是否出现买入或退出信号？

V1.1 要进一步回答：

- 为什么 BTC 正在上涨？
- 这是趋势性上涨还是短期情绪推动？
- 山寨币是否正在获得资金关注？
- 当前市场资金是在流入还是流出？
- 某个币的上涨有没有成交量和市场广度支持？
- 新闻事件是否可能改变原有趋势判断？

V1.1 的核心是建立一个市场情报层，为原有趋势评分提供更多解释信息。

## 2.2 功能模块

### 模块 A：市场全景监控

新增市场整体状态分析。

监控维度：

| 指标 | 作用 | 观察重点 |
|---|---|---|
| BTC 市值占比 | 判断市场资金集中程度 | BTC 是否持续吸收市场关注 |
| ETH/BTC | 判断 ETH 相对 BTC 强弱 | ETH 是否开始跑赢 BTC |
| TOTAL 市值 | 观察加密市场整体规模 | 整体市场扩张或收缩 |
| TOTAL3 | 观察排除 BTC、ETH 后的山寨币市场 | 山寨币是否形成整体行情 |
| 市场上涨比例 | 判断市场广度 | 上涨是否由少数币推动 |
| 成交额变化 | 判断交易活跃度 | 是否出现量能扩张 |
| BTC 波动率 | 观察系统性风险 | 是否出现异常波动 |

数据来源：

- Binance：交易对、成交量、K线、交易数据。
- CoinGecko 或 CoinMarketCap：市场市值及币种市值数据。
- TradingView 或其他可靠数据源：市场总市值指标，需核实授权及 API 可用性。

注意：TOTAL、TOTAL3 和 BTC Dominance 并不是 Binance 现货接口直接提供的数据，必须使用独立数据源，不能用 Binance 的交易对成交额简单替代。

新增页面：市场全景。

页面展示：

1. BTC、ETH、TOTAL、TOTAL3 的趋势状态。
2. BTC 市值占比变化。
3. ETH/BTC 趋势。
4. 市场上涨比例。
5. 市场成交额变化。
6. 市场整体风险等级。

输出市场状态：

- STRONG_BULL：强势上涨。
- BULL：上涨。
- NEUTRAL：震荡。
- BEAR：下跌。
- STRONG_BEAR：强势下跌。

市场状态需要结合多个指标，不允许仅凭 BTC 一根均线确定。

### 模块 B：衍生品市场分析

目的：观察合约市场的杠杆拥挤程度和多空交易行为。

新增指标：

| 指标 | 计算或含义 | 主要用途 |
|---|---|---|
| Open Interest | 未平仓合约数量或名义价值 | 判断杠杆资金参与程度 |
| Funding Rate | 永续合约资金费率 | 判断多空拥挤程度 |
| Taker Buy/Sell Volume | 主动买入和主动卖出成交量 | 判断主动交易方向 |
| Long/Short Ratio | 多空账户或持仓比例 | 辅助判断市场情绪 |
| Liquidation | 强平金额 | 判断杠杆清算冲击 |
| Basis | 合约价格与现货价格差 | 判断合约溢价或折价 |

分析规则：

1. 价格上涨 + OI 上升：可能有新增杠杆资金进入，需要结合成交量确认。
2. 价格上涨 + OI 下降：可能是空头回补推动，不能直接认定为健康上涨。
3. 价格下跌 + OI 上升：可能有新增空头或其他杠杆仓位进入。
4. Funding Rate 极端正值：提示多头拥挤风险。
5. Funding Rate 极端负值：提示空头拥挤，也可能存在反弹条件。
6. 大额强平：标记市场异常事件，观察是否改变原有趋势。

注意：

OI 上升不能简单解释为资金流入，资金费率也不能单独作为买卖信号。

数据来源：

Binance USDⓈ-M Futures Market Data。

优先核实官方接口：

- Open Interest History
- Funding Rate History
- Premium Index
- Taker Buy/Sell Volume
- Global Long/Short Account Ratio
- Top Trader Long/Short Ratio

所有接口都需要独立适配，记录数据源、采集时间和数据时间。

衍生品数据只作为现货策略的风险辅助特征，不直接生成做空交易信号。

### 模块 C：链上数据分析

目的：观察交易所之外的资产转移和链上活动。

首批建议观察 BTC、ETH。

指标：

| 指标 | 说明 | 作用 |
|---|---|---|
| Exchange Inflow | 流入交易所数量 | 观察潜在卖压 |
| Exchange Outflow | 流出交易所数量 | 观察资产转移行为 |
| Exchange Netflow | 流入减流出 | 观察交易所净流入 |
| Active Addresses | 活跃地址数量 | 观察网络活动 |
| Transaction Count | 链上交易数量 | 观察链上使用情况 |
| Large Transfers | 大额转账事件 | 识别异常资产转移 |

分析规则：

- 交易所净流入显著增加：标记潜在抛压。
- 交易所净流出持续增加：标记资产从交易所转移的现象。
- 活跃地址和交易量同步增加：标记网络活动增强。
- 大额转账发生：记录事件，不直接推断买卖意图。

特别注意：

链上转账不等于交易行为。交易所内部钱包归集、托管钱包调整、跨链桥转移都可能造成误判。

数据源建议：

- Glassnode
- CryptoQuant
- Coin Metrics
- 各公链官方浏览器/API

第一阶段先接入一个稳定数据源，避免多个数据源的口径不一致。

### 模块 D：新闻与事件情报

目的：建立新闻事件识别能力。

新闻类别：

1. 宏观经济：美联储利率、CPI、非农、美元指数。
2. 监管政策：美国 SEC、ETF、各国加密监管。
3. ETF 资金：BTC ETF、ETH ETF 净流入。
4. 交易所事件：上币、下币、暂停交易、故障。
5. 项目事件：协议升级、漏洞、黑客攻击、代币解锁。
6. 稳定币事件：USDT、USDC 发行、销毁、脱锚。
7. 行业重大事件：机构投资、破产、重大合作。

每条新闻需要结构化：

- 新闻标题。
- 原始链接。
- 发布机构。
- 发布时间。
- 事件发生时间（如果能够确定）。
- 涉及币种。
- 事件类别。
- 情绪倾向。
- 影响方向。
- 影响程度。
- 可信度。
- 是否为重复新闻。

情绪标签：

- POSITIVE
- NEGATIVE
- NEUTRAL
- UNCERTAIN

影响等级：

- LOW
- MEDIUM
- HIGH
- CRITICAL

新增新闻事件评分：

Event Impact Score = 事件影响程度 × 来源可信度 × 时效衰减系数。

时效衰减可以采用：

decay = exp(-ln(2) × age_hours / half_life_hours)

不同类型事件设置不同半衰期。

例如：

- 交易所暂停提现：短期高影响。
- 重大协议升级：中长期影响。
- 普通市场评论：低影响。

禁止将新闻情绪分直接等同于币价方向。

### 模块 E：多维趋势评分 V2

在 V1.0 原有 100 分趋势模型上增加辅助信息。

建议权重：

| 维度 | 权重 |
|---|---:|
| 趋势结构 | 25 |
| 动量 | 15 |
| 相对强度 | 15 |
| 成交量与主动交易 | 15 |
| 市场环境 | 15 |
| 衍生品风险 | 10 |
| 链上与事件情报 | 5 |
| 总计 | 100 |

说明：

链上与事件情报初期权重较低，是为了避免数据噪声主导交易信号。

如果某个数据源缺失，不允许直接按零分处理。

需要采用以下机制：

- 指标缺失时标记 unavailable。
- 对有效指标进行权重重新归一化。
- 同时降低数据置信度。
- 如果核心数据缺失，则不生成正式交易信号。

评分结果应拆成：

- Trend Score：趋势评分。
- Risk Score：风险评分。
- Sentiment Score：情绪评分。
- Data Confidence：数据置信度。
- Final Score：综合评分。

不建议将所有维度简单混成一个分数，因为趋势强但风险高，和趋势弱但风险低，是两种完全不同的市场状态。

### 模块 F：趋势变化预警

新增预警类型：

1. BTC 跌破 EMA200。
2. BTC 波动率异常上升。
3. ETH/BTC 趋势反转。
4. 山寨币市场广度快速下降。
5. 某币成交量突然放大。
6. 某币相对 BTC 强度明显提升。
7. OI 短时间异常增长。
8. Funding Rate 达到历史极端分位。
9. 链上大额转账。
10. 重大新闻事件。

每条预警记录：

- 预警类型。
- 触发对象。
- 触发时间。
- 触发指标。
- 触发阈值。
- 当前值。
- 风险等级。
- 解释文本。
- 是否已确认。
- 是否已解除。

通知方式：

- 系统站内通知。
- 邮件。
- Telegram Bot（可选）。

### 模块 G：趋势解释报告

每天自动生成市场分析报告。

报告结构：

1. 今日市场整体状态。
2. BTC 趋势分析。
3. ETH 趋势分析。
4. 山寨币市场广度。
5. 强势币排行榜。
6. 弱势币排行榜。
7. 衍生品风险。
8. 链上异常。
9. 重大新闻事件。
10. 明日重点观察指标。

报告必须区分：

- 数据事实。
- 指标计算结果。
- 模型推断。
- 不确定性。

AI 可以负责将结构化结果转化成自然语言，但不允许 AI 自行编造行情数据或未经验证的新闻。

# 三、V1.2：投资组合与资金管理系统

## 3.1 产品目标

V1.1 解决的是市场判断问题。

V1.2 解决的是资金如何配置的问题。

例如：

当前 BTC 趋势强，ETH 趋势中性，SOL 趋势较强。

但系统还需要回答：

- 当前账户应该持有多少 BTC？
- ETH 和 SOL 应该配置多少？
- 现金应该保留多少？
- 已经持仓的币是否应该减仓？
- 如果出现连续下跌，应该如何控制损失？
- 多个币同时出现买入信号，资金应该如何分配？

因此 V1.2 的核心是建立完整的 Portfolio Management。

## 3.2 功能模块

### 模块 A：投资账户管理

支持多个投资账户。

账户类型：

- SPOT：现货账户。
- PAPER：模拟账户。
- CUSTOM：自定义账户。

账户属性：

- 账户名称。
- 计价货币。
- 初始资金。
- 当前现金。
- 当前资产总值。
- 累计收益。
- 已实现收益。
- 未实现收益。
- 最大回撤。
- 创建时间。

第一版不连接 Binance 交易 API。

账户余额可以通过手动录入或导入 CSV 更新。

### 模块 B：资产持仓管理

支持记录每个币种的持仓。

字段：

- 交易账户。
- 币种。
- 持仓数量。
- 平均成本。
- 当前价格。
- 当前市值。
- 未实现盈亏。
- 已实现盈亏。
- 持仓占比。
- 持仓时间。
- 当前趋势评分。
- 当前风险等级。

持仓来源：

- 手动录入。
- CSV 导入。
- 模拟交易产生。

需要注意：

持仓成本必须考虑手续费，不能只用成交价格计算。

### 模块 C：投资组合风险管理

新增组合级风险控制。

建议默认配置：

| 风险项目 | 初始限制 |
|---|---:|
| 单币最大仓位 | 20% |
| 山寨币总仓位 | 40% |
| BTC + ETH 最大仓位 | 70% |
| 最低现金比例 | 15% |
| 单笔风险预算 | 组合净值的 0.5%～1% |
| 单日最大亏损预警 | 2% |
| 组合回撤预警 | 8% |
| 组合回撤严重预警 | 12% |

以上均为初始研究参数，不代表适合所有账户，应允许用户修改。

组合风险需要计算：

- 当前总仓位。
- 各币种仓位。
- BTC 和 ETH 集中度。
- 山寨币集中度。
- 组合波动率。
- 历史最大回撤。
- 组合 VaR（可选）。
- 组合 CVaR（可选）。
- 资产相关性矩阵。

### 模块 D：动态仓位建议

根据趋势评分、风险等级、波动率和资金约束计算建议仓位。

建议采用两层结构：

第一层：目标资产配置。

根据市场状态确定 BTC、ETH、山寨币和现金的目标比例。

第二层：单币仓位分配。

根据单币趋势评分、相对强度和波动率分配各币权重。

一个可解释的初始分配方法：

raw_weight_i = max(0, trend_score_i - threshold) / volatility_i

然后进行归一化，并施加：

- 单币最大仓位。
- 山寨币总仓位上限。
- 现金最低比例。
- 组合风险预算。
- 流动性限制。

注意：

不能只通过评分高低分配资金。高波动币可能评分很高，但风险调整后并不应该占据最大仓位。

建议增加：

Risk Adjusted Score = Trend Score / Volatility Adjustment。

最终仓位还需要经过 ATR 止损距离计算。

### 模块 E：买卖决策与持仓管理

将信号从单币维度升级为持仓维度。

状态：

- WATCH：观察。
- BUY_CANDIDATE：买入候选。
- HOLD：继续持有。
- REDUCE：建议减仓。
- EXIT：建议退出。
- BLOCKED：因风险限制禁止买入。

系统需要记录：

- 产生信号的原因。
- 建议仓位。
- 当前仓位。
- 建议调整数量。
- 预计手续费。
- 预计风险。
- 信号有效期。

例如：

SOL 当前仓位 10%，模型建议目标仓位 15%，系统可以给出：

建议增加仓位 5%，但需要通过现金比例、组合风险和市场状态检查。

不能直接因为评分从 70 上升到 80 就重复买入。

### 模块 F：模拟交易

建立 Paper Trading 模拟交易引擎。

模拟交易流程：

1. 策略产生信号。
2. 检查市场状态。
3. 检查资金和风险限制。
4. 生成模拟订单。
5. 根据下一根 K 线开盘价模拟成交。
6. 计算手续费和滑点。
7. 更新持仓和现金。
8. 更新账户净值。
9. 记录交易原因。

订单状态：

- CREATED
- SUBMITTED
- PARTIALLY_FILLED
- FILLED
- CANCELED
- REJECTED

成交记录：

- 成交时间。
- 交易币种。
- 买卖方向。
- 成交价格。
- 成交数量。
- 手续费。
- 滑点。
- 信号版本。
- 策略版本。

模拟交易必须严格遵循真实时间顺序，禁止使用尚未收盘的 K 线生成正式信号。

### 模块 G：模拟账户绩效分析

展示：

- 账户净值曲线。
- 累计收益。
- 日收益率。
- 周收益率。
- 月收益率。
- 年化收益。
- 最大回撤。
- Sharpe。

# 四、V1.3：智能策略与自适应研究平台

## 4.1 产品目标

V1.2 已经能够管理组合和模拟交易。

V1.3 要进一步解决：

- 不同市场环境下，哪种策略更有效？
- 趋势行情和震荡行情是否应该使用不同策略？
- 当前模型是否正在失效？
- 是否存在更适合当前市场的币种？
- 哪些指标真正对收益有贡献？
- 模型参数是否需要调整？

V1.3 的核心不是盲目引入 AI，而是建立策略研究、市场状态识别和模型评估体系。

## 4.2 功能模块

### 模块 A：市场状态识别模型

建立 Regime Detection。

市场状态：

- TRENDING_BULL：上涨趋势。
- TRENDING_BEAR：下跌趋势。
- SIDEWAYS：震荡。
- HIGH_VOLATILITY：高波动。
- LOW_VOLATILITY：低波动。
- EVENT_DRIVEN：重大事件驱动。

特征输入：

- BTC EMA 结构。
- ADX。
- ATR 百分比。
- BTC 收益率。
- ETH/BTC 相对强度。
- 市场广度。
- 成交量变化。
- 波动率分位数。
- Funding Rate。
- OI 变化。

第一阶段采用规则模型。

第二阶段可增加：

- K-Means。
- Gaussian Mixture Model。
- Hidden Markov Model。

模型输出：

- 当前市场状态。
- 状态概率。
- 状态持续时间。
- 状态切换概率。
- 主要判断依据。

不应直接把聚类结果视为真实市场状态，需要通过历史数据和后续收益表现验证其经济意义。

### 模块 B：多策略管理

建立策略注册中心。

初始策略：

1. EMA 趋势跟随策略。
2. Donchian 突破策略。
3. 动量策略。
4. 相对强度轮动策略。
5. 均值回归策略。
6. 波动率突破策略。

每个策略必须实现统一接口：

- initialize
- calculate_features
- generate_signal
- calculate_position
- calculate_exit
- get_parameters

策略统一输出：

- Strategy Code。
- Strategy Version。
- Symbol。
- Signal。
- Confidence。
- Target Weight。
- Stop Price。
- Explanation。
- Feature Snapshot。

### 模块 C：策略与市场状态匹配

根据市场状态决定策略是否启用。

示例：

| 市场状态 | 优先研究的策略 |
|---|---|
| 上涨趋势 | EMA 趋势跟随、Donchian 突破 |
| 下跌趋势 | 现金保护、降低持仓 |
| 震荡行情 | 均值回归 |
| 高波动行情 | 降低仓位、提高风险过滤 |
| 低波动行情 | 观察突破信号 |
| 事件驱动行情 | 暂停激进信号、等待确认 |

策略选择不是固定结论。

需要在历史数据上比较不同策略在不同市场状态下的表现，并且必须使用训练集和验证集确定匹配规则。

### 模块 D：策略组合与投票机制

多个策略可能同时对一个币产生不同信号。

例如：

- EMA 策略：BUY。
- Donchian 策略：BUY。
- 均值回归策略：SELL。
- 相对强度策略：BUY。

系统需要建立策略融合机制。

初始采用加权投票：

Ensemble Score = Σ(strategy_score_i × strategy_weight_i)

权重可以根据训练集和验证集的样本外表现确定，但不能直接根据最近几笔交易的盈亏频繁调整。

增加冲突处理：

- 强趋势策略优先于短周期反转策略。
- BTC 风险状态不允许时，限制山寨币新开仓。
- 高波动环境下降低策略仓位。
- 数据质量不足时禁止信号输出。

### 模块 E：参数优化

建立策略参数优化工具。

支持：

- Grid Search。
- Random Search。
- Bayesian Optimization（可选）。

优化参数：

- EMA 周期。
- Donchian 突破周期。
- ATR 止损倍数。
- ADX 阈值。
- 动量窗口。
- 评分权重。
- 仓位上限。

优化目标不能只选择最高收益。

建议采用多目标评价：

- Sharpe。
- Calmar。
- 最大回撤。
- 收益稳定性。
- 交易次数。
- 手续费占比。
- 不同市场状态下的表现。

必须设置参数稳定性约束。

如果参数从 20 改成 21，策略表现就大幅恶化，说明模型可能过拟合。

### 模块 F：模型健康度监控

增加 Model Monitoring。

监控：

- 最近 30 天策略收益。
- 最近 90 天策略收益。
- 实际回撤。
- 样本外表现。
- 信号准确率。
- 预测置信度。
- 特征分布变化。
- 模型输出变化。
- 策略失效情况。

增加模型状态：

- ACTIVE：正常。
- DEGRADED：表现下降。
- SUSPENDED：暂停使用。
- RETIRED：已退役。

当策略表现低于历史风险边界时，系统发出预警，而不是自动修改参数。

### 模块 G：AI 研究助手

这是 V1.3 可以引入的大模型能力。

AI 不直接负责生成未经验证的买卖信号，而是负责解释、研究和辅助分析。

功能：

1. 自然语言查询市场状态。
2. 分析 BTC 趋势变化。
3. 解释某个币为什么排名上升。
4. 对比两个策略的历史表现。
5. 分析某次交易为什么亏损。
6. 自动生成每日市场研究报告。
7. 查询某个策略在特定市场状态下的表现。
8. 根据历史数据提出策略研究假设。

示例问题：

- 为什么今天 SOL 的趋势评分高于 ETH？
- 最近 30 天 BTC 和 ETH 哪个趋势更稳定？
- 当前市场状态下，Donchian 和 EMA 哪个策略表现更好？
- 最近 10 次 SOL 买入信号中，有多少次最终盈利？
- 如果 BTC 跌破 EMA200，当前组合可能面临什么风险？

AI 的回答必须基于数据库查询结果、模型输出和历史回测数据。

所有关键数据应能追溯到具体查询结果。

禁止：

- AI 自行编造实时价格。
- AI 把新闻猜测当作事实。
- AI 直接修改正式策略参数。
- AI 未经验证自动调整资金仓位。
- AI 直接调用真实交易接口。

### 模块 H：策略研究实验室

建立独立研究工作台。

用户可以：

1. 选择币种。
2. 选择时间范围。
3. 选择策略。
4. 修改参数。
5. 选择市场过滤条件。
6. 执行回测。
7. 比较不同参数。
8. 生成策略研究报告。
9. 将经过验证的策略提交为候选版本。

研究实验必须有版本号。

例如：

- EMA_TREND_V1。
- EMA_TREND_V2。
- DONCHIAN_BREAKOUT_V1。
- MOMENTUM_ROTATION_V1。

每次实验记录：

- 实验编号。
- 策略版本。
- 参数配置。
- 数据区间。
- 数据版本。
- 训练区间。
- 验证区间。
- 测试区间。
- 回测结果。
- 实验结论。
- 创建人。
- 创建时间。

# 十、明确的产品边界

V1.1～V1.3 不应急于实现真实资金自动交易。

在没有充分验证之前：

- 不保存或使用 Binance 提币权限 API Key。
- 不自动执行真实买卖。
- 不允许 AI 直接修改正式策略。
- 不允许 AI 直接决定真实账户仓位。
- 不将回测收益描述为未来收益承诺。

只有当策略在历史回测、Walk-forward、样本外测试和长期模拟交易中都表现稳定，才考虑单独立项研究真实交易执行模块。

**最终目标：将 CTI 建设成一个以数据为基础、以量化模型为核心、以组合风险管理为约束、以 AI 为研究助手的加密资产投资研究平台。**
